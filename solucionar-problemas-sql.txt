📋 GUÍA DE ERRORES DE BASE DE DATOS (Supabase/PostgreSQL)
1. ERROR: null value in column "id" of relation "forms" violates not-null constraint
🔴 Error:
text
null value in column "id" of relation "forms" violates not-null constraint
🟢 Solución:
javascript
// Generar un ID antes de insertar
generateId() {
    const timestamp = Date.now().toString(36);
    const random = Math.random().toString(36).substring(2, 8);
    return `form_${timestamp}_${random}`; // o usar crypto.randomUUID()
}

// En el INSERT incluir el ID
const { data, error } = await supabase
    .from('forms')
    .insert([{
        id: this.generateId(),  // <-- IMPORTANTE
        title: title,
        questions: questions,
        slug: slug
    }])
📝 Nota:
La columna id es NOT NULL, siempre debe tener un valor

Si es tipo UUID, usar crypto.randomUUID()

Si es tipo TEXT, generar un ID único manualmente

2. ERROR: record "new" has no field "updated_at"
🔴 Error:
text
record "new" has no field "updated_at"
🟢 Solución A - Eliminar updated_at del código:
javascript
// NO incluir updated_at en el update
const { error } = await supabase
    .from('forms')
    .update({
        title: title,
        questions: questions
        // updated_at: new Date().toISOString()  <-- ELIMINAR
    })
    .eq('id', id);
🟢 Solución B - Añadir columna a la tabla (RECOMENDADO):
sql
ALTER TABLE forms ADD COLUMN updated_at TIMESTAMPTZ DEFAULT NOW();
ALTER TABLE responses ADD COLUMN updated_at TIMESTAMPTZ DEFAULT NOW();

-- Trigger para actualizar automáticamente
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ language 'plpgsql';

CREATE TRIGGER update_forms_updated_at 
    BEFORE UPDATE ON forms 
    FOR EACH ROW 
    EXECUTE FUNCTION update_updated_at_column();
📝 Nota:
El error 42703 significa "columna no existe"

Siempre verifica qué columnas tiene tu tabla antes de hacer UPDATE

Usa SELECT column_name FROM information_schema.columns WHERE table_name = 'tu_tabla';

3. ERROR: column "config" of relation "forms" does not exist
🔴 Error:
text

🟢 Solución A - Añadir columna:
sql
ALTER TABLE forms ADD COLUMN config JSONB DEFAULT '{}'::jsonb;
🟢 Solución B - Guardar config en otro lugar:
javascript
// Guardar en localStorage
localStorage.setItem('formpro_configs', JSON.stringify(configs));

5. ERROR: 400 Bad Request al hacer PATCH/UPDATE
🔴 Error:
text
PATCH .../rest/v1/responses?id=eq.xxx 400 (Bad Request)
🟢 Causas y soluciones:
Causa 1: JSON inválido
javascript
// ❌ MAL - datos con null
const correctionData = {
    answers: [true, null, false],  // null causa error
    scores: [1, null, 0]
}

// ✅ BIEN - limpiar nulls
const cleanAnswers = answers.map(a => a === null ? false : a);
const cleanScores = scores.map(s => parseFloat(s) || 0);
Causa 2: Columna no existe
javascript
// ❌ MAL - actualizar columna que no existe
await supabase.from('responses').update({ 
    correction: data,
    updated_at: new Date()  // si no existe la columna
})

// ✅ BIEN - solo columnas que existen
await supabase.from('responses').update({ 
    correction: data  // solo correction
})
Causa 3: Tipo de dato incorrecto
javascript
// ❌ MAL - enviar string donde espera JSONB
await supabase.from('responses').update({ 
    correction: JSON.stringify(data)  // string, no JSONB
})

// ✅ BIEN - enviar objeto directamente
await supabase.from('responses').update({ 
    correction: data  // objeto, se convierte a JSONB automáticamente
})
6. ERROR: 401 Unauthorized al acceder a una tabla
🔴 Error:
text
.../rest/v1/form_settings?select=* 401 (Unauthorized)
🟢 Solución:
sql
-- Habilitar RLS (Row Level Security) para la tabla
ALTER TABLE form_settings ENABLE ROW LEVEL SECURITY;

-- Crear política para permitir acceso
CREATE POLICY "Enable all access for authenticated users" 
ON form_settings 
FOR ALL 
USING (auth.role() = 'authenticated');

-- O simplemente deshabilitar RLS para pruebas
ALTER TABLE form_settings DISABLE ROW LEVEL SECURITY;
📝 Nota:
El error 401 significa que no tienes permisos para acceder a esa tabla

En desarrollo, puedes deshabilitar RLS temporalmente

En producción, configura las políticas correctamente

7. ERROR: 400 al hacer INSERT con columnas que no existen
🔴 Error:
text
INSERT error: {code: '42703', message: 'column "xxx" does not exist'}
🟢 Solución:
javascript
// ❌ MAL - incluir columnas que no existen
const formData = {
    id: newId,
    title: title,
    questions: questions,
    slug: slug,
    config: config,        // si no existe
    updated_at: new Date() // si no existe

const formData = {
    id: newId,
    title: title,
    questions: questions,
    slug: slug
    // solo estas columnas si son las que tiene la tabla
}
8. ERROR: Tipos de datos incorrectos en JSONB
🔴 Error:
text
invalid input syntax for type json
🟢 Solución:
javascript
// ❌ MAL - string no válido como JSON
const correctionData = "{answers: [true, false]}"  // falta comillas

// ✅ BIEN - objeto JavaScript
const correctionData = {
    answers: [true, false],
    scores: [1, 0]
}

// ✅ BIEN - si es string, usar JSON.stringify
const correctionData = JSON.stringify({
    answers: [true, false],
    scores: [1, 0]
})

📝 LISTA DE VERIFICACIÓN RÁPIDA
Antes de hacer cualquier operación en Supabase:

✅ SELECT:
¿Existe la tabla?

¿Existen las columnas que seleccionas?

¿Tienes permisos (RLS)?

✅ INSERT:
¿La columna id tiene valor (si es NOT NULL)?

¿Solo insertas columnas que existen?

¿Los tipos de datos son correctos?

¿Las claves foráneas existen?

✅ UPDATE:
¿Solo actualizas columnas que existen?

¿El WHERE tiene un valor válido?

¿Los tipos de datos son correctos?

¿La columna updated_at existe? (si la usas)

✅ DELETE:
¿Tienes permisos?

¿El WHERE tiene un valor válido?

📦 ESTRUCTURA RECOMENDADA DE TABLAS
Tabla forms:
sql
CREATE TABLE forms (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    questions JSONB NOT NULL,
    slug TEXT UNIQUE NOT NULL,
    description TEXT,
    allowmultiple BOOLEAN DEFAULT FALSE,
    showanswers BOOLEAN DEFAULT FALSE,
    config JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
Tabla responses:
sql
CREATE TABLE responses (
    id TEXT PRIMARY KEY,
    form_id TEXT REFERENCES forms(id) ON DELETE CASCADE,
    answers JSONB NOT NULL,
    correction JSONB DEFAULT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
